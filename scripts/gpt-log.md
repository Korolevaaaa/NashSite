## 1. Пластик ушёл?

Да.

Убраны главные причины пластикового ощущения:

- нет равномерной хроматики;
- нет растра внутри букв;
- нет псевдо-глянца;
- заливка стала матовой и плотнее к низу;
- циановый цвет теперь работает как контурный акцент, а не как неоновая подсветка.

Но возникла другая проблема: wordmark местами выглядит не как осознанный watermark, а как **почти случайный бледный outline за роботом**.

### `p=0`

Верхняя альфа заливки `0.06` практически не работает. Основную читаемость сейчас дают тонкие контуры, а не сама «чернильная» форма. Для тихого премиального watermark это допустимо, но ты уже находишься у нижней границы видимости.

Я бы поднял умеренно:

```css

  180deg,
  rgba(13, 17, 23, 0.08),
```

Не выше `0.25` на нижней точке. Иначе снова появится декоративная вывеска вместо фонового слоя.

### `p=0.15`

Сейчас:

```css

```

Фактические альфы становятся примерно такими:

- заливка: `0.028–0.10`;

## 2. Читается ли «несведение луча» на `p15`?

**Недостаточно.**

Математически сигнал есть:

- левый слой: примерно `-3.1px` по X;
- правый слой: примерно `+3.1px` по X;
- общая разница между ними: `6.2px`;
- по вертикали разница всего около `1.8px`;
- общий blur: `0.45px`.

Но визуально в скриншоте это считывается скорее как:

> «wordmark начал исчезать и слегка расплылся»

а не как:

> «две цветовые регистрации разошлись относительно исходной формы».

Причины:

1. `opacity` применяется ко всему сразу, включая основу.
2. `blur` применяется ко всему wordmark, а не только к эхо.
3. При исчезновении основы глазу не с чем сравнивать смещение.
4. Два симметричных слоя воспринимаются как расширение контура, а не как ошибка сведения.

На `p15` слово уже нужно рассматривать, чтобы увидеть механизм. Для hero-анимации это слишком объяснительно: эффект должен считываться периферийным зрением.

Отдельно: вертикальные cyan-линии рядом с роботом создают более явный «технический» сигнал, чем сам wordmark. В результате зритель может принять их за источник проекции, а надпись — просто за бледный фон.

## Вердикт: **НЕ ПРИНЯТО**

Сейчас это всё ещё выглядит как **размытая cyan-дымка / аэрогель**, а не как цельное шёлковое полотно. Заполнение геометрически есть, но визуально оно теряется из-за низкой плотности, мягких краёв и отсутствия читаемой поверхности.

### 1. Полотно или пятно?

**Пятно.** В обоих кадрах глаз считывает:

- мягкий градиент;
- одну светлую полосу;
- размытие по краям;
- отсутствие материальной поверхности.

Причина — слишком низкий контраст:

```glsl
a = inside * (0.40 + 0.34 * core)
u_opacity = 0.5–0.6
fade по краям
```

В центре фактическая альфа часто получается около `0.25–0.4`, а на светлом `#f4f4f4` это почти исчезает.

**Правки:**

```glsl
u_opacity:
about   = 0.72
process = 0.64
```

```glsl
a = inside * (0.58 + 0.30 * core);
```

Край сделать ощутимее:

```glsl
float inside = 1.0 - smoothstep(0.84, 0.985, abs(dN));
```

Сейчас диапазон `0.70–0.98` слишком долго растворяет полотно.

Добавить тонкую тёмную нижнюю кромку:

```glsl
float lowerEdge = 1.0 - smoothstep(0.90, 1.0, abs(dN));
float edgeLight = 1.0 - smoothstep(0.94, 1.0, abs(dN));

col += vec3(0.0, 0.18, 0.20) * lowerEdge * 0.18;
col += vec3(0.0, 0.75, 0.78) * edgeLight * 0.28;
```

Не размазывать край — у шёлка должен быть **контур**, пусть и мягкий.

### 2. Форма

Сейчас форма — **плоская сужающаяся лента**. Изгиб практически не читается. `wave = 0.075` недостаточно выразителен на таком масштабе, а наклон `0.10` даёт почти прямую ось.

Усилить крупный изгиб:

```glsl
float p1 = 4.8 * uv.x - u_flow * 0.17 + drift;
float p2 = 10.5 * uv.x - u_flow * 0.11 + u_seed * 2.5;

float wave =
    0.115 * sin(p1) +
    0.026 * sin(p2);
```

Добавить один длинный пространственный перегиб:

```glsl
float bend =
    0.065 * sin(uv.x * 2.2 + u_flow * 0.08 + seed) +
    0.035 * sin(uv.x * 5.0 - u_flow * 0.04);

float yc =
    0.52 +
    (uv.x - 0.5) * 0.10 +
    bend +
    swell +
    wave * env;
```

Это должно быть именно **одно широкое движение**, а не рябь. Клиент уже отверг «волокна», поэтому не повышать частоты агрессивно.

```glsl
float halfTh = mix(

```

Острие должно быть тонким, но всё ещё видимым. Текущие `0.034` плюс fade превращают правый конец в дым.

### 3. Цвет

Teal в текущем виде **не читается как цвет материала**. В кадре он присутствует только как слабый cyan-отблеск. На `#f4f4f4` нужно дать более плотное ядро.

Сделать градиент не «mist → cyan», а:

```glsl
vec3 darkTeal = vec3(0.0, 0.24, 0.26); // #003d42
vec3 teal     = vec3(0.0, 0.42, 0.44); // #006b70
vec3 cyan     = vec3(0.0, 0.79, 0.83); // #00c9d4

vec3 sheetColor(float x) {
    vec3 c = mix(darkTeal, teal, smoothstep(0.05, 0.45, x));
    c = mix(c, cyan, smoothstep(0.52, 0.92, x) * 0.55);
    return c;
}
```

Для центра полотна:

```glsl
col *= 0.95 + 0.22 * core;
```

Сейчас значение `центр * 1.08` почти не спасает изображение. Нужен не просто светлый центр, а **темнее тело + ярче отдельные складки**.

Спекулярные разводы сделать контрастнее, но не нитями:

```glsl
float spec = pow(
    0.5 + 0.5 * sin(uv.x * 12.0 + dN * 4.0 - flow * 0.55),
    5.0
);

col += vec3(0.0, 0.34, 0.38) * spec * 0.24;
```

Сейчас `pow(..., 3.0)` даёт слишком широкую мутную засветку. `5.0–6.0` даст более шёлковый, направленный блеск.

### 4. Верхняя блик-нить

Она должна быть видна как **контролируемая кромка**, а не как ещё один размытый слой.

Ширина:

```glsl
float topEdge = 1.0 - smoothstep(0.91, 0.985, dN);
```

Интенсивность:

```glsl
a += topEdge * 0.32;
col += vec3(0.0, 0.75, 0.78) * topEdge * 0.35;
```

Но не делайте её белой. Белый блик разрушит премиальность и сведёт эффект к пластику.

### 5. Что добавить для вау

**Да — перспективу и один дополнительный складочный слой.** Но не вторую самостоятельную волну.

#### Перспектива

Сейчас лист лежит фронтально и читается как SVG-лента. Нужна лёгкая деформация по глубине:

- левый край шире и немного выше;
- правый кончик уходит в перспективу;
- верхняя и нижняя кромки не параллельны.

Можно сделать в vertex shader или через UV:

```glsl
uv.y += 0.035 * (uv.x - 0.5) * (uv.y - 0.5);
uv.x += 0.018 * sin(uv.y * 3.14) * smoothstep(0.0, 1.0, uv.x);
```

Лучше — реальная деформация плоскости с `z`-смещением:

```glsl
pos.z += 0.08 * sin(uv.x * 3.0 + flow * 0.08) * sin(uv.y * 3.14);
```

#### Второй слой

Добавить не вторую волну, а внутреннюю складку:

Он должен появляться только внутри полотна и создавать ощущение перегиба, а не отдельной линии.

```js
blendFunc(gl.ONE, gl.ONE_MINUS_SRC_ALPHA)
```

Если используется обычный RGB, а включён premultiplied-блендинг, появится именно эта бледная молочная кайма. На светлом фоне ошибка особенно заметна.
